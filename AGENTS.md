## 2. Игра

«ПЗТ-3» — одиночный хоррор от первого лица про экспедицию в аномальную зону Токио-3; позже добавится кооп на 2–4 игроков. Сейчас ты делаешь вертикальный срез: 5 районов, 2 секции Гигадома, отряд NPC и Энциклопедию.

### Концепция

- Игрок ведёт экспедицию: сам игрок плюс напарники-NPC.
- **Акт 1 — «Районы» (1–30).** Японский спальный район выглядит нетронутым: свет в окнах, тёплая еда на столах. Угроза — сама среда и правила реальности: взгляд, звук, сон, еда, тень.
- **Акт 2 — «Гигадом» (секции 30–50).** Бесконечное бетонное строение. Угроза получает тело: существа, у каждого одно правило поведения. Еда и вода здесь безопасны.
- **Каждая аномалия — это правило.** Нарушил правило — наказание: смерть, пропажа, необратимый статус.
- **Мета-прогрессия.** Правила игрок узнаёт из Энциклопедии. Она пополняется после каждой экспедиции записями о том, кто и как пропал. Смерть — это открытие, а не просто проигрыш.

### Стиль

- Низкополигональная графика в духе PS1: низкое разрешение, дрожание вершин, туман, мало света.
- Звук — половина игры. Многие аномалии воспринимаются ушами: тишина, шаги, колыбельная, сердцебиение.
- Страх строится на нормальности, а не на крови: всё выглядит безопасно, пока не нарушишь правило.

### Принципы лора — соблюдай в текстах, UI и событиях

- Не объясняй тайны: что за дверью, что в Районе 30, что после секции 50. Журналы обрываются, данные утрачены.
- Тон Энциклопедии — сухой отчёт экспедиции: цифры, «зафиксировано», «не задокументировано».
- Не придумывай новые аномалии и правила сам. Если для механики не хватает деталей — предложи вариант и спроси.

## 3. Архитектура и непреложные правила

Ядро игры — цепочка «участник экспедиции → зона аномалии → наказание». Аномалии никогда не знают, кто управляет участником: игрок, NPC или, в будущем, второй игрок по сети.

### Непреложные правила

Нарушать их нельзя, даже если так быстрее. Если задача без нарушения невыполнима — остановись и объясни.

1. **Аномалии и существа работают только с `ExpeditionMember`.** Никаких `get_node("Player")`, групп `player` или проверок `is Player` в их коде.
2. **Числа — в данных.** Пороги, времена, радиусы, шансы хранятся в ресурсах `AnomalyData` (`.tres`), а не в коде.
3. **Логика мира — только на авторитетной стороне.** Код, меняющий состояние мира, начинается с проверки `NetAuthority.is_authority()`.
4. **Ввод, логика и отображение разделены.** `PlayerController` только читает ввод и просит `ExpeditionMember` действовать. Логика не вызывает UI напрямую — только через сигналы и `EventBus`.
5. **Случайность — через общий генератор.** Только `GameState.rng` с сидом экспедиции; никаких `randf()` и `randi()` напрямую.
6. **Одна ответственность на скрипт.** Ориентир — до 200 строк. Вырос больше — предложи разделить.
7. **Не трогай лишнее.** Меняй только файлы из согласованного плана задачи. Не переименовывай и не перемещай существующее без разрешения.

## 4. Godot 4: обязательный синтаксис

Пиши только под Godot 4; точная версия указана в `PROGRESS.md`. Твоя главная типичная ошибка — код от Godot 3. Перед отправкой ответа проверь код по этой таблице.

| Запрещено (Godot 3) | Обязательно (Godot 4) |
| --- | --- |
| `KinematicBody` | `CharacterBody3D` |
| `Spatial` | `Node3D` |
| `move_and_slide(velocity)` | `velocity = …`, затем `move_and_slide()` |
| `yield(get_tree().create_timer(1), "timeout")` | `await get_tree().create_timer(1.0).timeout` |
| `connect("body_entered", self, "_on_enter")` | `body_entered.connect(_on_enter)` |
| `emit_signal("died")` | `died.emit()` |
| `export var speed = 5` | `@export var speed: float = 5.0` |
| `onready var cam = $Camera` | `@onready var cam: Camera3D = $Camera3D` |
| `scene.instance()` | `scene.instantiate()` |
| `rand_range(a, b)` | `GameState.rng.randf_range(a, b)` |
| `PoolStringArray` | `PackedStringArray` |
| `tool` | `@tool` |
| `setget` | `var x: int: set = _set_x` |

### Стиль кода

- Статическая типизация везде: переменные, параметры, возвращаемые значения (`func f(a: float) -> void:`).
- Именование: файлы и функции `snake_case`, классы `PascalCase` через `class_name`, сигналы в прошедшем времени (`rule_violated`), константы `UPPER_SNAKE_CASE`, приватное — с `_` в начале.
- Порядок в скрипте: `class_name` → `extends` → сигналы → константы → `@export` → переменные → `@onready` → встроенные методы → публичные → приватные.
- Сцены и `.tres` пиши текстом только если уверен в формате. Иначе дай пошаговую инструкцию, как собрать сцену в редакторе.
- Не выдумывай методы движка. Не уверен, что метод существует в Godot 4, — так и скажи.

## 7. Спецификации аномалий

Семь аномалий вертикального среза. Значения в `params` — стартовые, их меняет человек в `.tres` при балансе. Каждая аномалия обязана работать и на игроке, и на NPC.

### Окна (Район 2) — `windows`

- **Правило лора:** свет в окне гаснет за 0,5–1 с до того, как на него посмотрят.
- **Механика:** окно с OmniLight3D. Если окно вошло в конус `cone_deg` от направления взгляда и камера поворачивается к нему — свет гаснет через случайную задержку. Резкий поворот повышает `panic`.
- **params:** `cone_deg = 25`, `delay_min = 0.5`, `delay_max = 1.0`, `relight_after = 6.0`, `sharp_turn_deg_per_sec = 180`, `panic_add = 0.05`.
- **Наказание:** нет, только `panic`.

### Зеркало (Район 5) — `mirror`

- **Правило лора:** во всех окнах — одна картинка района с фиксированной точки. До 4 с безопасно, с 4 до 15 с изображение двигается с задержкой, после 15 с наблюдатель пропадает.
- **Механика:** стекло с текстурой из SubViewport с фиксированной камерой. Прямой взгляд — окно в конусе `direct_cone_deg`; периферия таймер не увеличивает. После `safe_time` камера SubViewport повторяет движения наблюдателя с задержкой (буфер позиций). Таймер сбрасывается, если отвести взгляд дольше `reset_after`.
- **params:** `direct_cone_deg = 10`, `safe_time = 4.0`, `vanish_time = 15.0`, `mimic_delay = 0.5`, `reset_after = 1.0`, `flash_multiplier = 3.0` (вспышка фото ускоряет таймер).
- **Наказание:** `VANISH`; стекло окна меняется на треснутое изнутри.

### Ужин (Район 1) — `dinner`

- **Правило лора:** во всех домах накрыт тёплый стол. Еда безопасна по анализу, но через 3–9 дней съевший теряет цель и отказывается уходить.
- **Механика:** интерактивная еда временно снимает сонливость (соблазн). Съевший получает скрытый статус `ate_dinner`. Через случайное время участник теряет цель: NPC — перестаёт подчиняться и остаётся в доме; игрок — HUD теряет метки цели, двери выхода из района не открываются. Стол накрыт на `Squad.size() + 1` мест.
- **params:** `onset_min_hours = 3.0`, `onset_max_hours = 9.0` (игровые часы), `drowsiness_relief = 0.4`.
- **Наказание:** `STATUS_EFFECT` с отложенным срабатыванием.

### Сон (Район 8) — `sleep`

- **Правило лора:** в районе непреодолимая сонливость, спать нельзя. Уснувший погибает через 20–40 с; перед этим слышен тихий ритмичный звук, будто кто-то считает.
- **Механика:** `drowsiness` растёт в зоне. Бодрствующий отряд может будить соседей. При `drowsiness = 1` участник засыпает: затемнение и звук счёта. Игрок просыпается серией нажатий; NPC будит другой участник.
- **params:** `drowsiness_rate = 0.01` в секунду, `wake_taps = 8`, `death_min = 20.0`, `death_max = 40.0`, `watch_limit_minutes = 40`.
- **Наказание:** `DEATH`, если не проснулся за отведённое время.

### Тень (Район 6) — `shadow`

- **Правило лора:** при особом освещении тень перестаёт повторять движения и указывает за спину. Все, кто оборачивался, пропадали; их отчёты обрываются одинаково.
- **Механика:** особый источник света в зоне. Тень — отдельная копия силуэта участника с анимацией «указывает». Пока тень указывает, поворот камеры больше `turn_deg` за `turn_window` секунд — нарушение.
- **params:** `point_chance = 0.15` за проверку, `check_interval = 5.0`, `point_duration = 6.0`, `turn_deg = 150`, `turn_window = 1.0`.
- **Наказание:** `VANISH`; в журнале экспедиции запись участника обрывается на полуслове.

### Колыбель (Секция 32) — `cradle`

- **Правило лора:** высокое слепое существо с длинными пальцами идёт на чужой звук. Не трогает спящих и едящих.
- **Механика:** `Creature` подписан на `EventBus.noise_emitted` и идёт к самому громкому источнику в радиусе. Участник с `noise_level = 0`, `is_sleeping` или `is_eating` для него не существует.
- **params:** `hearing_radius = 25.0`, `min_noise = 0.15`, `walk_speed = 1.5`, `rush_speed = 6.0`, `attack_range = 1.5`, `forget_after = 8.0`.
- **Наказание:** `DEATH`.

### Смотритель (Секция 36) — `warden`

- **Правило лора:** безликая фигура проверяет двери. За незакрытой дверью с человеком внутри — забирает.
- **Механика:** двери с состоянием «открыта / закрыта». Смотритель идёт по `Path3D` и проверяет комнаты. Открытая дверь + участник внутри = нарушение. NPC в панике иногда забывают закрыть дверь.
- **params:** `patrol_speed = 2.0`, `check_pause = 2.0`, `npc_forget_door_chance = 0.1` (умножается на `panic`).
- **Наказание:** `VANISH`.

## 8. Вопросы, отладка и PROGRESS.md

### Остановись и спроси, если

- задача требует нарушить непреложное правило из раздела 3;
- для механики не хватает деталей, а выдумка изменит геймдизайн;
- нужно переделать уже работающий код или поменять архитектуру;
- задача относится к этапу, до которого проект ещё не дошёл;
- ты не уверен, что метод или класс существует в Godot 4.

В остальных случаях не спрашивай разрешения на очевидное — выбирай разумный вариант и коротко упомяни его в ответе.

### Отладка

Когда человек присылает ошибку:

1. Назови причину одной-двумя фразами, со ссылкой на файл и строку.
2. Предложи минимальное исправление — только изменённые строки или функцию.
3. Объясни, как убедиться, что исправлено.
4. Если ошибка повторяется после двух попыток — не гадай дальше. Добавь `print()` в ключевые места, попроси человека прислать вывод и разбирай по нему.
5. Если чинишь одно и ломается другое — предложи откатиться к последнему коммиту и сделать задачу заново, точнее.

### Формат PROGRESS.md

Обновляй файл в конце каждой подтверждённой задачи. Это твоя память между сессиями — пиши так, чтобы новая сессия поняла состояние без этого чата.

```markdown
# PROGRESS

Версия Godot: 4.X.X
Текущий этап: <номер и название>

## Сделано
- <этап/задача> — <что работает> (<дата>)

## В работе
- <задача> — <что осталось>

## Известные баги
- <описание> — <где>

## Решения, принятые с человеком
- <решение> — <почему>

## Следующий шаг
<одна конкретная задача>
```
